# 佛舍 · 鬼市 —— BOSS 战技术方案 & 可运行垂直切片

> 国风佛教暗黑动作游戏。视觉全部由 **Seedance 2.0** 离线预生成，视频之上叠加一层
> **UI + 交互层**。战斗形态对标《33 号远征队》(Clair Obscur: Expedition 33)：
> **回合制选招 + 实时弹反 + 固定/编排镜头**。本目录是 BOSS 战这一段的**正式技术实现**，
> 可在纯浏览器 H5 直接跑通。

---

## 0. 一句话结论（为什么这个架构成立）

「自由动作战斗」架在「预生成线性视频」上是物理死结（画面无法成为玩家每帧输入的连续函数）。
但 **33 号远征队式的回合制**把这个矛盾拆掉了：

| Exp33 机制 | 在预生成视频上的落地 |
|---|---|
| 回合制菜单选招（离散） | 选技能 → 播放对应片段。**纯 UI 层，零实时生成** |
| 固定 / 编排镜头 | 每段片段自带镜头 → **跨片段一致性最大的福音** |
| 敌方出招时的弹反 / 闪避定时 | 唯一的实时点 → 退化成「**定时输入 → 二选一分支视频**」，视频做得到 |

因此战斗 = 一个**视频片段状态机**，数值（血/气/架势）全活在 UI 层，视频只负责「演出」。

## 1. 已实现 & 已验证

本切片在 Chrome 实测跑通了完整循环，**零控制台报错**：

- ✅ 入场过场 → 玩家回合
- ✅ 普攻（含暴击）→ 伤害数字、蓄气、架势累积
- ✅ **弹反成功**（读 `video.currentTime` 判定窗口）→ 免伤 + 架势/蓄气 + 硬切弹反片段（白闪盖接缝）
- ✅ **弹反失手** → 受击片段 + 掉血 + 震屏
- ✅ 奥义「大藏天崩」→ 高耗大爆发
- ✅ **破防 BREAK** → 处决片段 + 架势清零 + 额外伤害
- ✅ **阶段转换**（一阶段血空 → 折命娘二相）
- ✅ 胜 / 败结算

## 2. 运行方式

纯静态站点，必须用 HTTP 起服（`file://` 下 `fetch` 会被拦）：

```bash
cd game
python3 -m http.server 8766
# 浏览器打开 http://localhost:8766
```

操作：点技能出招；BOSS 出招时按 **空格 / 点击屏幕 / 弹反键** 弹反；数字键 1/2/3 选招。

## 3. 架构总览（三层）

```
┌──────────────────────────────────────────────┐
│  交互/UI 层   game.js + index.html + style.css │  ← 回合制状态机、HUD、伤害数字、弹反判定
├──────────────────────────────────────────────┤
│  播放引擎     engine.js (ClipPlayer)           │  ← 双 video 无缝切换、预加载、白闪盖缝
│  音效层       sfx.js (WebAudio 合成占位)        │
├──────────────────────────────────────────────┤
│  视频层       clips/*.mp4  (Seedance 生成)      │  ← 「状态无关」演出片段
│  数据层       manifest.json                    │  ← 片段映射 + 战斗数值 + 弹反窗口
└──────────────────────────────────────────────┘
```

- **engine.js `ClipPlayer`**：两个 `<video>` 叠放，一可见一透明；换片段时先灌进透明的那个，
  就绪后交叉淡入并互换角色 —— 避免单 video 换 `src` 的黑屏。`transition:'cut'+flash` 用于
  命中/弹反瞬间，用一帧白闪盖住硬切接缝。`onTime(t)` 每帧回调，供弹反窗口判定。
- **game.js**：战斗状态机（见下）+ 全部数值 + DOM 渲染。
- **manifest.json**：唯一的「内容/平衡」配置，改数值/换片段/调弹反窗口都在这里，不动代码。

## 4. 战斗循环（状态机）

```
入场 intro
  └─→ 玩家回合 (菜单)
        ├─ 普攻 罗汉棍      → attack_light  → 伤害+蓄气+架势
        ├─ 奥义 大藏天崩    → attack_skill  → 大伤害+大破防 (耗气3)
        └─ 金刚冥想         → (无片段,buff) → 回血回气, 但直接进BOSS回合
  └─→ BOSS 回合
        播 boss_windup ──── 弹反窗口[start,end] ────┐
              成功 → parry_success (免伤,架势+,蓄气+) │ 读 video.currentTime 判定
              失手 → player_hit   (掉血,震屏)        ┘
  └─→ 架势满 → 破防 BREAK → break_execute (清架势+额外伤害)
  └─→ 一阶段血空 → boss_phase2 (二相, 重置血/架势)
  └─→ 二阶段血空 → 胜  /  玩家血空 → 败
```

## 5. 核心铁律：「状态无关片段」

**片段内绝不编码血量 / 伤害 / buff** —— 这些全部由 UI 层（数字、血条、状态图标）承载。
一段「奥义」片段，无论 BOSS 剩 90% 还是 10% 血都复用同一条。

这是把片段数从「组合爆炸」压回「有限可控」的关键。本 BOSS 仅需 ~10 条片段就跑通了
完整两阶段战斗：

```
intro / idle(循环) / attack_light / attack_skill /
boss_windup(+弹反窗口) / parry_success / player_hit /
break_execute / boss_phase2 / victory
```

正式版一个 BOSS 的量级估算：玩家技能 8~15 条 + BOSS 招式 10~20 条 ×（命中/弹反 2 结果）
+ 待机 + 阶段过场 ≈ **低百位数片段**。

## 6. manifest.json 关键字段

```jsonc
"clips": {
  "boss_windup": {
    "src": "clips/boss_windup.mp4",
    "parryWindow": { "prompt": 2.6, "start": 3.4, "end": 4.4 }
    //  prompt: 第几秒开始显示弹反提示环
    //  start~end: 判定为「弹反成功」的有效秒区间（读 video.currentTime）
    //  纯 H5 取宽窗口(~1s)，配合白闪盖接缝，无需帧级精度
  }
}
```

每条 BOSS 招式片段 = 自带一个 `parryWindow` 标注。这就是「实时层」与「线性视频」的接缝点：
**靠时间轴标注，而非实时生成**。

## 7. Web / H5 硬约束与无缝切换方案

发行约束：**必须纯浏览器 H5，不套壳**。对应工程取舍：

1. **无缝分支切换**：双 `<video>` 交叉淡入（本切片实现）。命中/弹反等硬切点用 `transition:'cut'`
   + 一帧白闪 `vfx-flash` 盖住接缝 —— 回合制天然有「打击那一下」可藏剪辑点，比动作游戏宽容。
2. **预加载**：本切片 boot 时把全部片段 `fetch` 成 blob 常驻内存（共 ~14MB），切换零延迟。
   ⚠️ **正式版片段数量大时不能全量预载**，需改为「滑动窗口预缓冲」：玩家选招期间预缓冲
   BOSS 的几种可能出招；BOSS 蓄力期间预缓冲「弹反成功 / 失手」两条分支。
3. **iOS Safari 注意**（待后台调研流给出精确数字后补充）：历史上对**同时解码的 video 元素数**
   与 `autoplay` 有严格限制。本引擎已加 `playsInline / webkit-playsinline / muted`（满足内联自动播放），
   且只用 2 个 video 元素。若 iOS 对双 video 并发解码仍有问题，备选是 **MSE/Managed-MSE 把片段
   拼成单条流**（仍是纯浏览器，不套壳）。
4. **编解码**：当前 H.264 main/yuv420p + `+faststart`，兼容性最好。

## 8. 把占位片段换成正式 Seedance 片段（生产管线）

当前 `clips/*.mp4` 是从概念视频 `1.mov` 裁出的**占位素材**（宽银幕裁切去掉了原烤进的 HUD，
但仍残留少量痕迹）。正式版工作流：

1. **先定锚点资产**：用 Seedance 多图参考能力，先生成并锁定
   - 角色设定图（佛舍 · 和尚，正面/侧面/持械）
   - BOSS 设定图（折命娘人形 + 怨灵蛛生形态）
   - 场景底板图（血色寺庙 · 固定机位）
2. **逐条生成片段**：每条都喂入上述锚点图作多图参考，**机位固定** → 跨片段一致性最大化。
3. **统一规格**：1280×~540 宽银幕 / H.264 / 去音轨（音频走独立层）/ 时长按 manifest。
4. **标注弹反窗口**：每条 BOSS 招式片段人工标 `parryWindow` 帧区间，写进 manifest。
5. **音频独立层**：⚠️ **不要用 Seedance 逐片段生成的音频**（跨片段不连续）。游戏要单独做
   一套连续 BGM + 采样音效层（替换 `sfx.js` 的占位合成音）。

> 模型抽象：建议把「文 → 片段」封装成一个 provider 接口，别把项目焊死在单一闭源模型上
> （Seedance 2.0 曾于 2026-03-15 因版权争议暂停部分全球发布，供应链有法律风险）。

## 9. 成本量级（粗估）

- 生成本身便宜：fal 参考价 ~$0.26 / 720p·5s。低百位数片段 × 重抽废片倍率（一致性 QA 下
  可能 3~10×）≈ **几百到小几千美元**的生成开销。
- **真正的成本在人力**：一致性校验、裁剪剪辑、弹反窗口标注、平衡调参。这才是大头。

## 10. 风险清单

| 风险 | 说明 | 缓解 |
|---|---|---|
| 跨片段一致性 | 视频生成头号难题，脸/服装/机位漂移 | 锚点资产库 + 固定机位 + 接受高废片率 |
| Web 性能 | 移动端多片段内存/解码 | 滑动窗口预缓冲；必要时 MSE 单流 |
| 模型法律状态 | Seedance 2.0 版权争议、发布暂停 | provider 抽象层，资产买断/留存 |
| 「看视频按键」廉价感 | FMV 通病 | 弹反紧张感 + 破防爽点 + 电影级演出（已是本切片的设计核心）|
